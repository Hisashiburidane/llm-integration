# 【AI编码开发】EnchantForge：让 AI 看见应用

`AI编码开发`

## 应用知道的，AI 也该知道

多数所谓的“AI 化”，仍然是在现有系统外增加一次模型调用。换一个页面，就重新描述页面
结构、拼接 Prompt、声明 Tools，再把模型输出接回业务流程。这不是架构，只是重复集成。

真正缺少的，是 AI 与应用之间的上下文基础设施。页面结构、当前状态和业务函数本来就在
应用里，不应该再让模型猜一遍。

**EnchantForge 是一个面向现有 Vue 应用的 AI 集成框架。**它把应用显式提供的信息组织
成 AI 上下文，并把应用函数转换为模型可以调用的 Tools。

![EnchantForge 门户首页](./01-portal-home.png)

## 上下文来自应用

组件可以通过 wrapper、组合式函数或应用级 API 提供描述、Schema、状态和函数。组件
挂载时加入上下文，卸载后自动移除。

应用可以只提供一个组件、一个页面，或当前任务需要的范围。AI 获得的是足够完成任务的
信息，无关状态不会进入上下文。

```vue
<Enchant prompt="根据用户输入填写表单，但不要提交">
  <EnchantExpressForm />
</Enchant>
```

## 让函数，成为 AI 的能力

应用函数可以注册为 Tools。AI 负责理解需求、选择和组合 Tools；参数 Schema、Policy
和最终执行仍由应用代码定义。

从修改一个字段到运行完整业务流程，注册函数的范围决定了 AI 在应用中的执行边界。
聊天框只是入口之一：Aura、自定义 Agent、语音转写和业务事件都可以使用同一份上下文
与 Tools。

## 应用示例

### 自然语言填写表单

用户输入收件人、电话、地址和物品信息，模型生成结构化工具调用并填写 Vue 表单。应用
只允许填写草稿，不会自动提交。

<!-- 截图：填写完成的快递表单 -->

### 分析数据，也操作页面

可配置 Dashboard 包含航空、北京空气质量、NYC Taxi 和 OpenTelemetry 数据。Agent
可以读取多个 Panel 的查询结果，回答问题，并高亮支撑结论的图表。回答与页面操作来自
同一轮 Tool Calling。

<!-- 截图：完成分析并高亮多个 Panel 的 OpenTelemetry Dashboard -->

### 不从聊天框开始

实时坐席辅助示例由模拟 ASR 转写触发 Agent。它可以查询演示订单接口、检索示例知识、
更新工单草稿，并向人工坐席显示提示。Aura 可以负责展示，也可以不参与执行。

<!-- 截图：ASR、订单信息、工单草稿和坐席提示 -->

## 从注册到执行

EnchantForge 管理组件注册、上下文捕获、Tool 导出、执行校验和结果记录。页面结构进入
metadata，实时数据由 Tools 按需读取，业务状态和副作用留在应用。

页面内 Debug 可以查看模型请求、工具参数、执行结果和错误；可选的 OpenTelemetry
Adapter 可以把运行过程接入现有观测系统。

<!-- 截图：Debug 中的模型请求与工具执行记录 -->

## 可以直接运行

核心库、基础示例、Dashboard 应用、数据处理和中英文门户保持独立。模型通过
OpenAI-compatible API 接入，配置从 `.env` 读取。

一个命令可以准备数据、初始化配置并启动完整 Dashboard 示例：

```bash
pnpm demo
```

模型或数据服务不可用时，页面会显示错误，不会使用预制回答。

## 关于名字

语言模型能够理解和生成，却无法像传统程序一样被完全枚举和计算。`Enchant` 代表这种
近似魔法的能力；`Forge` 代表上下文、Schema、Policy 和执行器构成的工程边界。

EnchantForge 不试图消除模型的不确定性，而是让它在应用中拥有清楚、稳定、可以检查的
接口。
